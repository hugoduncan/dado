# Dado Goals

Dado aims to improve the speed and quality of all aspects of developing
and maintaining a system or library.  It should be particularly useful
as the number of concepts, abstractions, and interactions between them,
increase.

## Stakeholder benefits

It should benefit the product owners, the developers and the end users.

Product owners get to clearly understand the scope and
features of the system.

Developers have clear requirements, and improved code quality.

End users have improved documentation and better understanding of the system.

## General benefits

- Reduce time required to implement features

- Improve quality across scope, architecture, and implementation

- Enable easy evolution of system as requirements change

- Improve robustness and reliability

- Enable consistency in cross cutting concerns such as error handling,
  logging, etc.

- Maintain living, accurate documentation

- Make routine task updates simple and efficient

- Simpler project on-boarding through thorough documentation and project history

## General Approach to achieving goals

These improves will come through being very explicit about the design
and implementation process, by automation of routine tasks, and by code
generation.

It recognises that development is an iterative process, across scope,
architecture and implementation, and that all three develop and become
more concrete over time.

It aims to avoid stagnation in the documentation and implementation of
the system by making updates simple in response to new or changed
requirements.

Dado will lean heavily on AI to achieve these goals.

## Non-goals

- Enforcement of specific business processes
- Required formal sign-offs or approvals
- Integrated measurement or tracking systems
- Mandated development workflows
- Prescribed risk management processes
